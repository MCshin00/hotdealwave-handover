# 업무 규칙과 함정 기록

## 입력과 경계

- 대상 저장소 경로, 추출 결과 디렉터리(`analysis/<대상>`), 서비스의 애플리케이션 이름 목록을 받는다. 대상은 고정 커밋을 읽기만 하고 빌드하거나 실행하지 않는다.
- 이 Skill, [항목 형식](../../../docs/format/README.md)과 [항목 스키마](../../../docs/format/knowledge.schema.json), `out/analysis.json`의 추출 배열, 지정한 추출 디렉터리의 서비스·관계 파일과 저장된 `responses/`, 대상 코드·설정만 읽는다. 형식 예시를 사실로 쓰지 않는다.
- `.env`, `.env.*`, `.local/`, `eval/`, 기존 `knowledge/` 결과는 읽지 않는다. `out/analysis.json`에 이미 항목이 있으면 `knowledge` 배열도 읽지 않는다. 추출 배열만 선택해 읽는다.
- 코드와 JSON을 직접 읽고 항목을 직접 쓴다. 별도 모델 API, 추출 스크립트, 서버 재가동, 응답 재호출은 하지 않는다. 환경변수는 이름만 쓰고 비밀값·로컬 절대경로를 남기지 않는다.

## 읽는 순서

1. 추출된 서비스와 대상 설정의 `spring.application.name`을 대조해 요청받은 서비스를 찾는다. 디렉터리 이름으로 애플리케이션 이름을 추정하지 않는다.
2. `out/analysis.json`의 해당 서비스 엔드포인트·Feign 호출·Kafka 발행·구독에서 출발해 실제 처리 코드를 따라간다. 영향받는 항목 ID는 이 네 추출 배열에 있는 값을 그대로 쓴다.
3. 처리 경로의 분기와 상태 전이, 계산, 검증 규칙, 예외와 오류 응답, 역할별 권한을 읽는다. 조건과 결과를 함께 확인하고, 함수 이름이나 주석만으로 실제 동작을 단정하지 않는다.
4. Feign 호출은 대상의 응답 생성 코드와 호출 쪽 수신 클래스를 함께 읽는다. JSON 필드 이름·타입과 수신 필드가 맞는지, 받은 값을 이후 코드에서 어떻게 사용하는지까지 따라간다. 저장된 응답이 있으면 실제 필드와 값을 함께 확인한다.
5. 숨은 동작이나 처리 누락은 관련 분기·호출·후속 처리까지 읽고 설명한다. 실행 결과를 보지 않았다면 코드에서 확인한 조건과 동작만 적는다. 저장소 밖의 설정값이나 실제 연결을 추정하지 않는다.

## 항목 작성

- 선택한 서비스마다 `knowledge/<대상>/<spring.application.name>.json` 하나를 쓴다. `<대상>`은 입력 추출 디렉터리의 대상 이름이다. 형식은 `schemaVersion: 1`과 `items` 배열이며, 근거를 갖춘 항목이 없으면 빈 배열을 쓴다.
- 항목마다 `service`, `title`, `description`, `evidence`, `affectedIds`, `source`, `discoveryPath`, `confirmationStatus`를 쓴다. 설명에는 발생 조건과 실제 동작·영향을 적는다. 등급이나 별도 분류를 만들지 않는다.
- `source`는 `AI 해석`, `confirmationStatus`는 `미확인`으로 쓴다. 확인 상태는 개발자만 정한다. 검증 경고의 판정을 대신하거나 `판정` 출처를 만들지 않는다.
- 코드에 근거가 있는 항목만 쓴다. `evidence`에 대상 루트 기준 `파일:줄`을 붙이고, 여러 파일에 걸친 동작은 연결되는 줄을 함께 넣는다. 줄 번호는 실제 파일에서 확인한다.
- 저장된 응답을 근거로 쓰면 `analysis/<대상>/responses/<파일>.json:줄`을 함께 붙이고 `discoveryPath`를 `실제 응답`으로 쓴다. 코드 근거만 있으면 `코드`로 쓴다. 응답이 없는데 호출 결과를 만들어 쓰지 않는다.
- `affectedIds`에 영향받는 엔드포인트·Feign 호출·Kafka 발행·구독 ID를 넣는다. 추출 결과에 없는 ID를 새로 만들지 않는다.

## 저장 전 점검과 보고

- JSON 문법·스키마 필수 필드·허용 값, 근거 파일과 줄, 영향 ID의 존재를 점검한다. 설명이 맞는지는 개발자가 확인하며 검증기 통과가 개발자 확인을 대신하지 않는다.
- 결과 파일 위치와 서비스별 항목 수, 코드를 따라갔지만 근거를 확정하지 못한 부분을 보고한다. 기존 항목·평가 자료와 대조하지 않는다.
