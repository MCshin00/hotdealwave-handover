# 코드에서 구조 추출

## 입력과 경계

- 대상 저장소 경로, 결과 디렉터리 경로, 추출할 서비스의 애플리케이션 이름 목록(생략하면 전체), 다시 쓸 절 목록(생략하면 전체)을 받는다. 대상은 읽기만 하고 빌드하지 않는다.
- 읽는 것은 대상 코드·설정, 이 Skill, [추출 결과 형식](../../../docs/format/README.md)과 그 스키마뿐이다. 형식 속 예시를 추출 사실로 쓰지 않는다. 기존 추출 결과는 읽지 않는다(관계 단계의 서비스 파일과, 절 목록을 받았을 때 그 서비스 파일만 예외).
- `.env`, `.env.*`, `.local/`은 열지 않는다. 환경변수는 이름만 쓴다.
- 코드를 직접 읽고 JSON을 직접 쓴다. 추출 스크립트를 만들거나 별도 모델 API를 부르지 않는다.

## 가정하는 구성

| 부분 | 가정 |
|---|---|
| 서비스 | `build.gradle`과 `src/main/java`가 있는 디렉터리 하나가 서비스 하나, 설정은 `application*.yml` |
| 게이트웨이 | Spring Cloud Gateway의 YAML 경로 규칙, 인증 필터의 토큰 허용 목록 |
| 내부 호출 | OpenFeign |
| 비동기 | Spring Kafka. 토픽은 설정 키 → YAML의 `${환경변수}` → 루트 `docker-compose.yml`의 `- 이름=${이름}` |
| 오류 응답 | 오류 코드 enum, `@RestControllerAdvice`의 `@ExceptionHandler`, 게이트웨이 인증 필터의 응답 종료 |

가정과 다른 부분은 만들지 않고 완료 보고에 적는다.

## 추출 순서

1. 서비스: 매번 저장소 전체에서 서비스를 찾고 `spring.application.name`을 확인한다. 디렉터리 이름으로 서비스 이름을 추정하지 않는다. 선택한 서비스마다 2~9단계를 한다.
2. API: 클래스·메서드 매핑을 합쳐 HTTP 메서드와 전체 경로를 구하고, 파라미터와 요청·응답 DTO를 따라가 형식대로 기록한다. 외부 타입의 구조나 프레임워크 기본값은 만들지 않는다.
3. Feign: 대상 서비스 파일에 기대지 않고 대상 컨트롤러를 직접 읽어, 클라이언트 이름·대상 서비스·HTTP 메서드·전체 경로로 엔드포인트 ID를 정한다. 메서드 이름이 비슷하다고 연결하지 않는다.
4. 게이트웨이: 경로 규칙으로 외부 경로를 만들고, 토큰 허용 목록과 실제 비교 코드로 토큰 필요 여부를 정한다. 서비스 안의 권한 검사와 섞지 않는다.
5. Kafka 선언: 구독·발행·DLQ를 찾는다. 발행 토픽은 래퍼와 메서드 인자를 거슬러 호출 지점까지 따라간다.
6. Kafka 토픽: 코드의 설정 키 → 기본 YAML → 그 서비스의 compose `environment`를 형식대로 잇는다.
7. 환경변수·외부 자원: 형식대로 기록한다. 환경변수 `location`은 YAML과 그것을 참조하는 `@Value`면 전체 설정 키, compose면 `environment`다. compose는 서비스의 `environment` 항목만 본다. 근거 없는 자원은 만들지 않는다.
8. 오류 응답: 오류 코드 enum 상수, 예외 처리기, 게이트웨이 필터의 거부 응답, `@EnableSpringDataWebSupport`의 페이지 직렬화 설정을 형식대로 기록한다. 처리기의 상태·오류 코드·메시지는 오류 응답 DTO 생성자까지 따라가 어디서 정해지는지 적고, 처리기 안의 조건에 따라 갈리면 `분기`로 적는다.
9. 누락 확인: 매핑·Feign·Kafka 선언과 `@ExceptionHandler`·오류 코드 enum을 직접 검색해 추출 항목과 대조한다. 주석 속 선언은 항목으로 만들지 않는다. 검증 경고를 피하려고 사실이나 근거를 바꾸지 않는다.
10. 관계: 1단계에서 찾은 모든 서비스 파일이 있을 때 따로 실행하고, 서비스를 하나라도 다시 추출했으면 다시 한다. 서비스 파일의 Kafka 발행·구독을 대조해 `kafkaLinks`를 쓰고, 엔드포인트·Kafka 구독의 핸들러에서 서비스·포트·어댑터·래퍼를 따라가 같은 서비스의 Feign 호출·`kafkaTemplate.send` 발행에 닿는 `calls`를 쓴다. 엔드포인트 핸들러에서 같은 방식으로 따라가 같은 서비스의 예외 생성 줄에 닿는 `throws`를 쓰고, 그 예외를 받는 처리기를 상속을 따라 정한다. 거치는 길의 `catch`가 잡는 예외는 쓰지 않고, `join()` 등으로 감싸여 나가는 예외는 감싼 예외의 처리기로 잇는다. 셋을 `relations.json` 하나로 낸다. Feign 대상 ID가 대상 서비스 파일에 없으면 완료 보고에 적는다.

## 근거 선택

- 모든 사실에 대상 루트 기준 `파일:줄`을 붙인다. 관계에는 양쪽과 중간 전달 줄을 넣는다. 줄을 꾸미거나 다른 선언으로 바꾸지 않는다.
- 엔드포인트·Feign 호출·Kafka 항목·선언 목록의 첫 근거는 매핑·`@FeignClient`·리스너·발행·DLQ 선언 줄이다. 래퍼 호출 줄로 대신하지 않는다.
- `path.evidence`에는 클래스(또는 클라이언트) 매핑 → 메서드 매핑 줄만 순서대로 넣는다.
- 필드·파라미터는 이름이 있는 선언 줄, 타입은 클래스 이름 또는 사용 타입이 있는 줄, 어노테이션은 그 어노테이션 줄이다.
- 서비스 이름은 설정 값 줄, 경로 규칙은 ID·URI·Path·재작성 값 줄, 허용 목록은 상수 이름·경로·메서드 줄이다. 외부 경로에는 엔드포인트·경로 규칙의 첫 근거와 재작성 근거를, 토큰 판정에는 허용 목록과 비교 코드 줄을 넣는다.
- Kafka `topicKey`에는 전체 키가 적힌 코드 줄을 넣는다.
- `calls`에는 출발 항목의 첫 근거, 거치는 호출 줄, 도착 지점 줄을 순서대로 넣는다. `throws`의 도착 지점 줄은 예외 생성 줄이다.
- 오류 코드는 상수 선언 줄, 예외 처리기는 `@ExceptionHandler` 줄 다음에 상태·본문을 정하는 줄과 그 값을 채우는 DTO 생성자 줄, 게이트웨이 거부는 조건 줄 다음에 상태를 정하는 줄과 응답을 끝내는 줄, 페이지 직렬화는 어노테이션 줄이다.
- 빈 문자열 값에는 부재를 확인한 선언이나 경로 규칙 줄을 붙인다.

## 결과 작성과 점검

- 서비스 하나마다 결과 디렉터리의 `services/<spring.application.name>.json` 하나만 쓴다. 절 목록을 받았으면 기존 파일에서 그 절(최상위 키, 관계는 `relations.json`의 키)만 바꾸고 나머지는 글자 하나 바꾸지 않는다.
- 어노테이션 문자열 인자는 Java 이스케이프를 푼 값으로 쓴다(`"\\d"` → `\d`).
- 저장 전 JSON 문법, 스키마 구조, ID 참조, 근거 줄, 상태 필드·환경변수 값·절대경로가 없는지 확인한다.
- 완료 후 결과 파일 위치, 정하지 못한 부분, 관계 단계 실행 여부와 Feign 대상 ID 누락을 짧게 보고한다. 검증 통과를 직접 선언하지 않는다.
