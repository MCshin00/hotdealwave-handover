# 코드에서 구조 추출

## 입력과 경계

- 대상 저장소 경로, 결과 디렉터리 경로, 추출할 서비스의 애플리케이션 이름 목록(생략하면 전체)을 받는다. 대상은 지정된 고정 커밋의 읽기 전용 소스로 취급하며 수정하거나 빌드하지 않는다.
- 입력은 대상 코드·설정, 이 Skill, [추출 결과 형식](../../../docs/format/README.md)과 그 서비스·관계 스키마이며, 관계 단계에서만 서비스 파일을 추가로 읽는다. 형식의 필드·타입·분류·범위를 따른다. 형식에 등장하는 특정 대상의 이름·예시를 추출 사실로 쓰지 않는다.
- 도구 저장소의 `out/`, `docs/`(위 형식 문서·스키마만 예외), `eval/`, `knowledge/`, `.local/`은 읽거나 검색하지 않는다. 형식·스키마 외의 문서 링크도 따라가지 않는다. 서비스 추출에는 기존 추출 결과를 참고하지 않는다.
- 대상에서도 `.env`, `.env.*`, `.local/`은 열거나 검색하지 않는다. 환경변수는 이름만 기록하고 값·비밀값을 출력하지 않는다. 결과에 로컬 절대경로를 쓰지 않는다.
- 파일 목록·텍스트 검색·줄 번호를 붙인 읽기로 코드를 직접 해석하고 JSON을 직접 작성한다. 추출 프로그램이나 스크립트를 만들거나 실행하지 않는다. 별도 모델 API도 호출하지 않는다.

## 가정하는 구성

| 부분 | 가정 |
|---|---|
| 서비스 | `build.gradle`과 `src/main/java`가 있는 디렉터리 하나가 서비스 하나, 설정은 `application*.yml` |
| 게이트웨이 | Spring Cloud Gateway의 YAML 경로 규칙, 인증 필터의 토큰 허용 목록 |
| 내부 호출 | OpenFeign |
| 비동기 | Spring Kafka. 토픽은 설정 키 → YAML의 `${환경변수}` → 루트 `docker-compose.yml`의 `- 이름=${이름}` |

가정과 다른 부분은 만들어 내지 않고 완료 보고에 적는다.

## 추출 순서

1. 매번 저장소 전체의 빌드 파일과 소스 디렉터리로 서비스를 찾고, 설정의 애플리케이션 이름을 확인한다. 디렉터리 이름과 서비스 이름을 추정으로 같게 만들지 않는다. 항목의 `service`와 엔드포인트·Feign·Kafka ID 앞부분에는 애플리케이션 이름(`spring.application.name`)을 쓰고, 디렉터리 이름은 `service.directory`와 근거 경로에 쓴다. 애플리케이션을 실행하는 compose 서비스 키를 `service.composeService`에 키 선언 줄·대응을 정한 줄의 근거와 함께 기록하고, compose에 없거나 대응을 정할 수 없으면 `value: null`로 둔다. 선택한 서비스마다 2~8단계를 진행한다.
2. 컨트롤러의 클래스·메서드 매핑을 합쳐 HTTP 메서드와 전체 경로를 구한다. 파라미터 바인딩과 요청·응답 DTO를 따라가 필드·제네릭 인자·검증 어노테이션·JSON 이름을 형식대로 기록한다. 외부 타입의 구조나 프레임워크 기본값을 만들어 내지 않는다.
3. Feign 클라이언트 선언과 매핑 메서드를 읽는다. 내부 호출은 대상 서비스 파일의 존재에 기대지 않고 컨트롤러를 직접 읽어 클라이언트 이름·대상 서비스 이름·HTTP 메서드·전체 경로로 유일한 엔드포인트 ID를 정한다. 메서드 이름의 유사성으로 연결하지 않는다. 명시된 외부 URL 호출은 구분한다.
4. 게이트웨이의 URI·Path·RewritePath와 토큰 허용 목록 및 실제 비교 코드를 읽는다. 대상 서비스와 재작성 전후 경로가 맞는 외부 경로만 만든다. 토큰 필요 여부는 경로·메서드 비교에 근거하며, 서비스 내부 권한 검사와 혼동하지 않는다.
5. Kafka 구독·발행·DLQ 선언을 찾는다. 발행 토픽은 private 래퍼와 여러 메서드의 인자 전달을 호출 지점까지 거슬러 추적한다. 같은 발행 선언에 서로 다른 토픽 전달 경로가 있으면 각각 기록하고, 원래 선언 목록은 위치별로 한 번만 기록한다.
6. Kafka 토픽의 코드 참조 → 설정 키 → 기본 YAML → 같은 서비스의 compose 환경변수 전달을 형식의 기본 프로필·동일 이름 전달 조건에 맞춰 잇고 사슬의 각 줄을 보존한다. 문자열 토픽은 형식대로 별도 취급하고 이름이 비슷한 후보 연결은 만들지 않는다.
7. 환경변수 이름을 서비스·프로필·사용 위치별로 기록한다. `location`은 YAML과 그것을 참조하는 `@Value`면 전체 설정 키, compose면 `environment`다. compose는 서비스의 `environment` 항목만 본다. 외부 자원은 형식의 종류별로 설정과 사용 코드를 모으되 근거 없는 자원은 만들지 않는다. 환경변수 값·연결 값·버킷 이름은 `null`로 둔다.
8. 매핑·Feign·Kafka 선언 목록과 추출 항목을 대조해 누락을 확인한다. 주석 속 선언을 실행 중인 API나 발행으로 만들지 않는다. 검증 경고를 피하려고 사실이나 근거를 바꾸지 않는다.
9. 관계 단계는 1단계에서 찾은 모든 서비스 파일이 있을 때 별도로 실행하며, 서비스를 하나라도 다시 추출했으면 다시 한다. 서비스 파일의 Kafka 발행·구독을 대조해 양쪽 사슬이 확인되고 환경변수 이름이 같을 때만 `relations.json`에 연결을 쓴다. Feign 대상 ID가 대상 서비스 파일에 없으면 완료 보고에 적는다.

## 근거 선택

- 모든 항목과 하위 사실에 대상 루트 기준 `/` 구분 상대경로와 1부터 시작하는 줄 번호의 `파일:줄`을 붙인다. 이름·값·타입이 실제로 적힌 줄을 고르고, 관계에는 양쪽과 중간 전달 근거를 포함한다.
- 엔드포인트·Feign 호출의 첫 근거는 메서드 매핑 줄, Feign 클라이언트는 `@FeignClient` 줄로 둔다. 선언 목록과 Kafka 발행·구독의 첫 근거는 해당 매핑·리스너·발행·DLQ 선언 줄이다. 래퍼 호출 줄로 대체하지 않는다.
- 조합한 API 경로의 `path.evidence`에는 경로 조합 순서대로 클래스 또는 클라이언트 매핑 → 메서드 매핑 줄만 넣는다. 다른 근거는 상위 항목에 둔다.
- 필드·파라미터는 이름이 있는 선언 줄, 타입은 클래스 이름 또는 사용 타입이 있는 줄, 어노테이션은 해당 어노테이션 줄을 인용한다. `jsonName`에는 필드 선언과 이름을 결정한 getter 또는 Lombok 어노테이션 줄을 함께 넣는다.
- 서비스 이름은 설정 값 줄, 경로 규칙은 ID·URI·Path·재작성 값 줄, 허용 목록은 상수 이름·경로·메서드 줄을 각각 해당 사실에 붙인다. 없는 속성의 빈 문자열에는 부재를 확인한 선언이나 경로 규칙 줄을 붙인다.
- Kafka `topicKey`에는 전체 키가 적힌 코드 줄, `environment`에는 YAML과 해당 서비스의 compose 전달 줄을 넣는다. `kafkaLinks`에는 양쪽 compose 줄을 포함한다. 실제 토픽 값을 모르면 `topicName`은 `null`이어도 환경변수 참조 근거를 남긴다.
- Feign 대상에는 호출·서비스 이름·대상 컨트롤러 근거를, 외부 경로에는 엔드포인트·경로 규칙의 첫 근거와 재작성 근거를 포함한다. 토큰 판정에는 허용 목록과 비교 코드 근거를 붙인다.
- 실제 근거를 보존하며 줄을 꾸미거나 다른 선언으로 바꾸지 않는다.

## 결과 작성과 점검

- 서비스 하나를 추출하면 지정된 결과 디렉터리의 `services/<spring.application.name>.json` 하나만 쓴다(`schemaVersion: 1`, UTF-8). 추출 결과에는 모든 깊이에서 `status`를 빼고, `checks`·`warnings`도 쓰지 않는다.
- 코드·설정으로 정할 수 없는 사실은 `value: null`과 관련 근거를 남긴다. 빈 문자열은 형식에서 부재·해당 없음으로 정한 경우에만 쓰며, 빈 배열은 항목이 없을 때 쓴다. 어노테이션의 문자열 인자는 Java 이스케이프를 푼 값으로 기록한다(소스의 `"\\d"`는 `\d`).
- 형식의 정렬 순서와 ID 규칙을 따른다. 게이트웨이 경로 ID처럼 대상 코드에 적힌 값은 유지하며, 서비스·관계 스키마의 최상위 배열과 하위 구조를 빠뜨리지 않는다.
- 저장 전 JSON 문법, 필수 구조, ID 참조, 근거 줄과 순서, 금지된 상태 필드·환경변수 값·절대경로가 없는지 확인한다. 관계 단계 외에는 출력을 입력으로 재사용하지 않는다.
- 완료 후 결과 파일 위치, 코드에서 정하지 못한 부분·형식의 한계, 관계 단계 실행 여부와 Feign 대상 ID 누락을 짧게 보고한다. 검증 통과나 확인 상태를 직접 선언하지 않는다.
